## 1. 참조

### 참조란

- **참조(reference)** 는 이미 존재하는 객체에 붙이는 또 다른 이름이다.
- 새 메모리를 잡지 않고, 원본 변수와 **바인드**되어 별칭 역할만 한다.
- 함수끼리 데이터를 주고받을 때 복사 없이 전달하는 수단이 된다.

```cpp
int score = 92;       // 원본 변수
int& rScore = score;  // score의 또 다른 이름
```

- 참조를 선언할 때 자료형은 원본과 **정확히 일치**해야 한다.
- 선언과 동시에 반드시 초기화해야 한다. (`int& r;` 는 컴파일 오류)

### 참조 관계는 바뀌지 않는다

한 번 맺어진 참조 관계는 스코프를 벗어날 때까지 유지된다. 다른 변수로 갈아탈 수 없다.

```cpp
int score = 92;
int& rScore = score;
int num = 80;

rScore = num;   // score의 값이 80이 됨 (참조 대상은 여전히 score)
```

> [!warning] 가장 헷갈리는 지점
> `rScore = num;` 은 "rScore가 num을 참조하게 하라"가 **아니다.**
> "rScore가 가리키는 대상(= score)에 num의 값을 대입하라"이다.
> 참조에는 재바인딩 문법 자체가 존재하지 않는다.

#### 참조 다중성

- 하나의 변수에 여러 개의 참조를 붙일 수 있다.
- 반대로 하나의 참조가 여러 변수를 가리킬 수는 없다.

```cpp
int score = 92;
int& r1 = score;
int& r2 = score;   // 가능: 같은 객체에 이름이 셋
```

### 값 읽기와 변경

- 참조 관계가 맺어지면 원본과 참조 중 무엇을 써도 같은 값에 접근한다.
- 둘 중 무엇으로 대입해도 원본 값이 바뀐다.
- 단, `const` 한정자가 붙으면 그 이름으로는 **읽기만** 가능하다.

| 케이스 | 원본 변수                     | 참조 변수                      | 결과     |
| :-: | :------------------------ | :------------------------- | :----- |
|  1  | `int name = value;`       | `int& rName = name;`       | 가능     |
|  2  | `const int name = value;` | `int& rName = name;`       | **오류** |
|  3  | `int name = value;`       | `const int& rName = name;` | 가능     |
|  4  | `const int name = value;` | `const int& rName = name;` | 가능     |

- **2번이 오류인 이유**: 읽기 전용인 대상에 수정 가능한 이름을 붙이는 것은 권한 확대라 금지된다. 방향이 반대인 3번은 허용된다.
- **3번의 의미**: `const` 는 **그 이름을 통한 접근 권한**만 제한한다. 원본 `name` 으로는 여전히 수정할 수 있고, 그 결과를 `rName` 으로 읽으면 바뀐 값이 보인다. 즉 "값이 안 변한다"는 보장이 아니라 "이 통로로는 안 바꾼다"는 보장이다.

### 함수와 참조

함수의 **커뮤니케이션**이란 데이터를 전달(argument → parameter)하고 리턴하는 것을 말한다.

#### 전달 방식 비교

|                     | 값으로 전달          | 참조로 전달           |
| :------------------ | :-------------- | :--------------- |
| 문법                  | `void f(int x)` | `void f(int& x)` |
| 복사                  | 발생              | 없음               |
| argument와 parameter | 독립적             | 동일한 객체           |
| parameter 수정 시      | argument 그대로    | argument도 바뀜     |
| 적합한 경우              | 작은 자료형          | 클래스처럼 큰 객체       |

```cpp
void byValue(int x) { x = 100; }
void byRef(int& x)  { x = 100; }

int a = 1, b = 1;
byValue(a);   // a는 여전히 1
byRef(b);     // b는 100
```

#### 리턴 방식 비교

|         | 값으로 리턴     | 참조로 리턴          |
| :------ | :--------- | :-------------- |
| 문법      | `int f()`  | `int& f()`      |
| 복사 비용   | 큰 객체일수록 높음 | 없음              |
| 지역변수 리턴 | 가능         | **불가 (댕글링 참조)** |

참조로 리턴할 때 지역변수를 돌려주면 안 되는 이유는, 함수가 끝나는 순간 지역변수가 파괴되어 **이미 사라진 메모리를 가리키는 참조**가 남기 때문이다.

```cpp
int& bad() {
    int local = 5;
    return local;   // 위험: 함수 종료 시 local 파괴
}
```

리턴해도 되는 것:

- 참조 매개변수 — 호출한 쪽이 소유하므로 함수 종료 후에도 살아 있다.
- 정적(`static`) 지역변수
- 전역변수, 클래스 멤버 변수

## 2. 포인터

### 주소와 주소 연산자

- 모든 변수는 최소 1바이트 이상의 메모리를 차지한다. 크기는 `sizeof()` 로 확인할 수 있다.
- **변수의 주소** 는 그 변수가 차지하는 첫 번째 바이트의 주소를 의미한다.
- 주소를 얻으려면 **주소 연산자 `&`** 를 쓴다.

```cpp
int score = 92;
cout << &score;         // score의 주소
cout << sizeof(score);  // 4
```

### 포인터 변수

- **포인터 자료형** 은 값이 주소인 복합 자료형이다. 원본 자료형 뒤에 `*` 를 붙여 만든다.
- 리터럴 주소가 아니라 **기존 변수의 주소**로 초기화한다.
- 포인터의 자료형은 가리킬 대상의 자료형과 일치해야 한다.

```cpp
bool flag = true;
bool* pFlag = &flag;
```

#### 간접 참조

포인터가 가리키는 값에 접근할 때는 **간접 참조 연산자 `*`** 를 쓴다.

```cpp
cout << pFlag;    // 주소
cout << *pFlag;   // 값 (true)
*pFlag = false;   // 원본 flag가 false로 바뀜
```

> [!note] `*` 기호의 두 가지 역할
> 선언할 때의 `*` 는 "이건 포인터 자료형"이라는 표시이고,
> 사용할 때의 `*` 는 "가리키는 값을 꺼내라"는 연산자다. 같은 기호지만 하는 일이 다르다.

### `const` 한정자

| 케이스 | 원본 변수                     | 포인터 변수                      | 결과     |
| :-: | :------------------------ | :-------------------------- | :----- |
|  1  | `int name = value;`       | `int* pName = &name;`       | 가능     |
|  2  | `const int name = value;` | `int* pName = &name;`       | **오류** |
|  3  | `int name = value;`       | `const int* pName = &name;` | 가능     |
|  4  | `const int name = value;` | `const int* pName = &name;` | 가능     |

- **1번**: 원본으로도 포인터로도 수정 가능하다.
- **2번**: 오류. 읽기 전용 변수의 주소를 수정 가능한 포인터에 담는 것은 권한 확대라 금지된다. 참조의 2번 케이스와 같은 원리다.
- **3번**: 원본으로는 수정 가능하고, 포인터로는 읽기만 가능하다.
- **4번**: 양쪽 모두 읽기 전용이다.

> [!tip] `const` 위치에 따른 차이
> ```cpp
> const int* p;   // 가리키는 값을 못 바꿈 (p는 다른 곳을 가리킬 수 있음)
> int* const p;   // p 자체를 못 바꿈 (가리키는 값은 수정 가능)
> ```
> 참조는 애초에 재바인딩이 불가능하므로 아래쪽 성질을 기본으로 갖고 있다.
> 그래서 참조에 `const` 를 붙이는 방법은 한 가지뿐이다.

### 포인터의 포인터

`*` 를 두 번 붙이면 포인터를 가리키는 포인터가 된다.

```cpp
int score = 92;
int*  p  = &score;
int** pp = &p;

cout << **pp;   // 92
```

### 널 포인터

아무것도 가리키지 않는 포인터를 **널 포인터**라고 한다.

```cpp
int* p = nullptr;   // C++11 이후 권장
int* q = 0;         // 구식 표기
```

- `0x0` 주소를 가리킨다는 뜻이 **아니라**, 유효한 대상이 없다는 표시다.
- 널 포인터를 간접 참조하면 프로그램이 죽는다. 쓰기 전에 검사해야 한다.

```cpp
if (p != nullptr) {
    cout << *p;
}
```

- 참조에는 이런 "비어 있음" 상태가 없다. **포인터를 쓰는 가장 큰 이유 중 하나**가 이것이다.

### 함수와 포인터

#### 포인터로 전달

객체의 **주소를 전달**하고, 호출된 함수에서 간접 참조로 원본을 다룬다.

```cpp
void byPtr(int* x) { *x = 100; }

int a = 1;
byPtr(&a);   // a는 100
```

> [!important] 자주 하는 오해
> 포인터로 전달은 **주소값을 복사해서 넘기는 것**이다. 즉 포인터 변수 자체는 값으로 전달된다.
> - `*x = 100;` → 원본이 바뀐다. 같은 메모리를 가리키기 때문이다.
> - `x = &other;` → 호출한 쪽의 포인터는 안 바뀐다. `x` 는 복사본이기 때문이다.
>
> 참조로 전달에는 이 구분 자체가 없다. parameter가 곧 argument이기 때문이다.

#### 포인터로 리턴

참조로 리턴과 같은 제약이 있다. 지역변수의 주소를 리턴하면 이미 파괴된 메모리를 가리키게 된다.

#### 참조와 포인터 중 무엇을 쓸까

| 상황           | 선택       |
| :----------- | :------- |
| 큰 객체를 읽기만 함  | `const&` |
| 값을 수정해야 함    | `&` (기본) |
| "없음"을 표현해야 함 | `*`      |
| 대상을 옮겨가며 순회  | `*`      |
| 동적 메모리 / 배열  | `*`      |

기본은 참조를 쓰고, **참조로 표현할 수 없을 때만** 포인터로 내려간다.

## 3. 배열과 포인터

### 배열 이름과 포인터

자료형 `t` 의 원소 N개짜리 배열을 선언하면 시스템은 연속된 N개의 메모리 위치를 잡는다. 배열 이름은 표현식에서 쓰일 때 **첫 번째 원소의 주소로 변환**된다.

```cpp
int arr[5];
int* p = arr;   // arr이 &arr[0] 으로 변환됨
```

> [!note] 배열 이름은 포인터 변수가 아니다
> 별도의 포인터 객체가 메모리에 생기는 것이 아니라, 필요할 때 주소로 **변환(decay)** 되는 것뿐이다.
> 확인 방법: `sizeof(arr)` 는 20(= 4 × 5)이지만 `sizeof(p)` 는 8이다.
> `arr++` 가 안 되는 것도 상수 포인터라서가 아니라, 애초에 대입할 수 있는 객체가 아니기 때문이다.

### 포인터 산술 연산

포인터는 정수 자료형이 아니지만 산술 연산자를 적용할 수 있고, 결과로 포인터가 나온다. **자료형 크기 단위로** 움직인다는 점이 핵심이다.

| 연산                 | 의미                   |
| :----------------- | :------------------- |
| `p + n`, `p - n`   | n개 원소만큼 앞뒤로 이동       |
| `p++`, `p--`       | 한 원소만큼 이동            |
| `p += n`, `p -= n` | n개 원소만큼 이동한 뒤 대입     |
| `p1 - p2`          | 두 위치의 **인덱스 차이** (정수) |
| `p1 < p2`          | p1이 더 앞쪽 원소를 가리키는가   |

```cpp
int arr[5] = {10, 20, 30, 40, 50};
int* p = arr;

cout << *p;        // 10
cout << *(p + 2);  // 30
p++;
cout << *p;        // 20
```

- `arr[i]` 는 `*(arr + i)` 와 완전히 같은 표현이다.
- 포인터끼리 **더하는** 연산은 의미가 없으므로 지원하지 않는다.

### 배열을 함수에 전달하기

매개변수를 포인터로 선언하면 배열을 받을 수 있다. 아래 두 선언은 완전히 동일하다.

```cpp
void print(int arr[], int size);
void print(int* arr, int size);
```

- 주소만 전달되므로 **크기 정보가 사라진다.** 그래서 크기를 별도 매개변수로 함께 넘겨야 한다.
- 함수 안에서 원본을 수정하지 않는다면 `const` 를 붙인다.

```cpp
void print(const int arr[], int size);
```

### 2차원 배열

2차원 배열을 넘길 때는 **열의 크기를 컴파일 시점에 알려줘야** 한다. 원소의 위치를 계산하려면 한 행의 길이를 알아야 하기 때문이다.

```cpp
const int COLS = 4;

void print(int arr[][COLS], int rows);    // 열 크기는 자료형의 일부
void print(int (*arr)[COLS], int rows);   // 위와 동일한 의미
```

- 행의 개수는 별도의 정수 매개변수로 전달한다.

## 4. 메모리 관리

### 1. 코드 메모리

* 코드 메모리는 프로그램 코드를 보유하는 영역.
* 코드 메모리는 프로그램이 종료될 때 해제됨.

### 2. 정적 메모리

* 장작 메모리는 전역 객체와 정적 객체를 보유하는 영역.
* 프로그램이 종료되면 모든 객체를 정리하고 메모리 위에서 해제.

### 3. 스택 메모리
* 스택 메모리는 함수의 지역 변수와 매개변수를 보유.
* 후입선출 방식이다.

### 4. 힙 메모리

* 컴파일 시점에 객체의 크기를 모른다면 런타임 시점에 메모리에 객체를 만들어야 한다. 
* 힙 메모리는 런타임 시점에 객체를 저장할 때 사용하며, 동적 메모리라고도 부른다.
* C++는 스택에 있는 객체만 이름을 가질 수 있으므로 힙 메모리는 객체명이 없다.
* 힙 메모리에 생성한 객체는 스택 메모리에 있는 포인터로 가리켜야 한다.
* 즉, 런타임 시점에 메모리에 객체를 만드는 작업은 스택과 힙을 모두 사용하는 것이다.

#### new & delete

| 이름    | 연산자        | 표현식             |
| ----- | ---------- | --------------- |
| 객체 할당 | `new`      | `new type`      |
| 배열 할당 | `new[]`    | `new[] type`    |
| 객체 제거 | `delete`   | `delete type`   |
| 배열 제거 | `delete[]` | `delete[] type` |

##### 힙 메모리 사용 시 주의점

* 메모리 할당 없이 제거하기
* 제거 없이 메모리 할당하기
* 허상 포인터 사용
