# 기존 리포지터리 3개 정리하기

`CPP-Study`, `Python-Study`, `cpp_project` 의 내용은 **이미 이 리포지터리 안에
전부 들어와 있습니다.** 파일 79개 전부 blob 해시까지 대조해 원본과 동일함을
확인했고, 세 리포지터리의 커밋 히스토리도 `git subtree` 로 그대로 붙였습니다.

그래도 **삭제는 되돌릴 수 없으므로** 아래 순서를 지켜 주세요.
확인이 끝나기 전에는 지우지 마세요.

## 1단계 — 통합본 확인 (지우기 전 필수)

새 리포지터리를 아무 데나 클론해서 내용이 다 있는지 눈으로 확인합니다.

```powershell
cd $env:TEMP
git clone https://github.com/0328matthew/Programming-Study.git check
cd check
git log --oneline | Measure-Object -Line     # 옛 커밋들이 다 보여야 합니다
tree /F "C++"
tree /F "Python"
```

히스토리가 살아 있는지도 확인해 보세요. 전체 로그에 세 리포지터리의
옛 커밋이 그대로 섞여 있어야 합니다.

```powershell
git log --oneline
```

> **주의 — `git log -- "C++/개념"` 은 옛 커밋을 보여주지 않습니다.**
> `git subtree` 는 옛 커밋을 *그때의 경로 그대로* 붙입니다. 즉
> `aa26e30` 안에서 파일 경로는 아직 `Ch.7 클래스와 생성자.md` 이지
> `C++/개념/Ch.7 클래스와 생성자.md` 가 아닙니다. 커밋은 전부 있지만
> 경로 필터에는 걸리지 않습니다. 같은 이유로 `--follow` 도 통합
> 지점을 넘지 못합니다.

옛 커밋의 내용을 꺼낼 때는 **그 시절 경로**를 쓰세요.

```powershell
git show aa26e30 --stat
git show "aa26e30:Ch.7 클래스와 생성자.md"
```

## 2단계 — 로컬 볼트를 새 리포지터리로 연결

데스크톱의 기존 볼트 폴더가 아직 옛 리포지터리를 바라보고 있다면 원격만
바꿔 주면 됩니다.

```powershell
cd "C:\Users\0328m\Programming Study"     # 실제 볼트 경로로
git remote -v                              # 지금 뭘 보고 있는지 확인
git remote set-url origin https://github.com/0328matthew/Programming-Study.git
```

폴더 구조를 새 규칙(`C++/개념`, `C++/예제`, …)에 맞춰 옮겨야 한다면
`tools\migrate-local-vault.ps1` 을 쓰세요. `-WhatIf` 로 먼저 미리보기 하세요.

```powershell
.\tools\migrate-local-vault.ps1 -Vault "C:\Users\0328m\Programming Study" `
    -CppProjects "C:\Users\0328m\cpp_project" `
    -PythonProjects "C:\Users\0328m\python_projects" -WhatIf
```

## 3단계 — 로컬 백업 (안전망)

지우기 직전에 옛 리포지터리를 통째로 하나 떠 둡니다. 몇 초면 됩니다.

```powershell
mkdir "C:\Users\0328m\_repo_backup"
cd "C:\Users\0328m\_repo_backup"
git clone --mirror https://github.com/0328matthew/CPP-Study.git
git clone --mirror https://github.com/0328matthew/Python-Study.git
git clone --mirror https://github.com/0328matthew/cpp_project.git
```

`--mirror` 는 모든 브랜치·태그·히스토리를 포함합니다. 혹시 뭔가 빠졌다면
여기서 되살릴 수 있습니다. 한 달쯤 두었다가 지우세요.

## 4단계 — GitHub 에서 삭제

리포지터리 삭제는 GitHub API 로 자동화하지 않았습니다 — 되돌릴 수 없고,
실수하면 복구 창구가 사실상 없기 때문입니다. 직접 눌러 주세요.

각 리포지터리에서 **Settings** → 맨 아래 **Danger Zone** →
**Delete this repository** → 이름을 입력해 확인.

- https://github.com/0328matthew/CPP-Study/settings
- https://github.com/0328matthew/Python-Study/settings
- https://github.com/0328matthew/cpp_project/settings

> GitHub 는 삭제 후 90일 이내라면 지원팀을 통해 복구해 주는 경우가 있지만,
> 보장되지 않습니다. 3단계 백업을 꼭 먼저 하세요.

삭제 후 로컬에 남은 옛 클론 폴더들도 정리합니다. (3단계 백업은 남겨 두세요.)

Remove-Item -Recurse -Force "C:\Users\0328m\cpp_project"
