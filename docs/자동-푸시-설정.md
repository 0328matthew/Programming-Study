# 자동 커밋·푸시 설정

## 먼저 알아 둘 것

**VS Code 에는 "창이 닫힐 때" 실행되는 훅이 없습니다.** 태스크의 `runOn` 은
`folderOpen` 하나뿐이고, 종료 이벤트는 확장 프로그램조차 안정적으로 잡지
못합니다. 그래서 "닫으면 푸시"를 두 겹으로 구현했습니다.

| 방식 | 언제 푸시되나 | 설정 필요? |
|---|---|---|
| **① 유휴 감지 동기화** | 편집을 멈추고 20초 뒤 | 없음 (폴더 열면 자동) |
| **② `code --wait` 래퍼** | 창을 닫는 바로 그 순간 | 아래 3번 (1회) |

①만으로도 실질적으로는 충분합니다 — 창을 닫을 때쯤이면 이미 푸시가 끝나
있으니까요. ②는 마지막 몇 초의 편집까지 확실히 챙기는 안전망입니다.

## 1. 볼트 클론

```powershell
cd "C:\Users\0328m"
git clone https://github.com/0328matthew/Programming-Study.git "Programming Study"
```

폴더 이름에 공백을 쓰기 싫으면 `Programming-Study` 그대로 두어도 됩니다.

## 2. 유휴 감지 동기화 (설정 불필요)

VS Code 로 볼트 폴더를 열면 `.vscode/tasks.json` 의 **자동 동기화 시작**
태스크가 `folderOpen` 으로 실행됩니다.

처음 열 때 *"이 폴더의 자동 태스크를 허용하시겠습니까?"* 를 물으면
**Allow / 허용**을 누르세요. 한 번만 물어봅니다.

터미널 패널에 이런 로그가 흐르면 정상입니다.

```
[14:03:11] INFO  자동 동기화 시작 — C:\Users\0328m\Programming Study
[14:03:11] INFO  변경 후 20초간 조용하면 커밋·푸시합니다.
[14:05:40] OK    커밋:  2 files changed, 31 insertions(+)
[14:05:42] OK    푸시 완료
```

기다리지 않고 지금 당장 올리고 싶으면
`Ctrl+Shift+P` → `Tasks: Run Task` → **지금 바로 커밋 & 푸시**.

## 3. 창을 닫는 순간 푸시 (권장, 1회 설정)

`tools\study.cmd` 로 볼트를 열면 됩니다. 바로가기를 만들어 작업표시줄에
고정해 두면 평소 VS Code 아이콘 대신 쓸 수 있습니다.

PowerShell 을 주로 쓴다면 프로필에 함수로 넣어 두세요.

```powershell
notepad $PROFILE      # 파일이 없다고 하면 만들겠다고 답하세요
```

아래를 붙여넣고 저장합니다.

```powershell
function study {
    & "C:\Users\0328m\Programming Study\tools\study.ps1"
}
```

이제 터미널에서 `study` 만 치면 됩니다. 볼트를 열기 전에 `pull --rebase` 를
먼저 하고, 창을 닫으면 커밋·푸시까지 끝냅니다.

> `code` 명령이 없다고 나오면 VS Code 에서 `Ctrl+Shift+P` →
> `Shell Command: Install 'code' command in PATH` 를 실행하세요.

## 4. 실행 정책 (한 번만)

PowerShell 스크립트가 차단되면 현재 사용자에 한해 허용합니다.

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

`.vscode/tasks.json` 과 `study.cmd` 는 이미 `-ExecutionPolicy Bypass` 로
호출하므로 보통은 이 단계 없이도 동작합니다.

## Obsidian Git 플러그인과 함께 쓰기

이미 Obsidian Git 을 쓰고 계시죠 (기존 커밋 메시지가 `vault sync ...` 였습니다).
같은 폴더에 두 개의 자동화가 붙으면 `index.lock` 충돌이 날 수 있어서,
`auto-sync.ps1` 은 `.git\autosync.lock` 파일로 자기 차례를 지킵니다.
그래도 Obsidian 쪽 설정을 아래처럼 맞춰 두면 충돌이 거의 사라집니다.

Obsidian → 설정 → Git:

| 항목 | 값 | 이유 |
|---|---|---|
| Vault backup interval | `10` 분 | 너무 잦으면 VS Code 쪽과 겹칩니다 |
| Auto pull interval | `10` 분 | |
| Pull updates on startup | 켬 | 다른 기기 변경사항을 먼저 받음 |
| Push on backup | 켬 | |
| Commit message | `vault sync {{date}}` | 기존과 동일하게 유지 |

**둘 다 열어 두지 않는 것이 가장 안전합니다.** 노트는 Obsidian 에서,
코드는 VS Code 에서 — 한 번에 하나씩 여세요.

## 문제가 생기면

**푸시가 안 되고 로그에 `pull --rebase 실패` 가 뜬다**
다른 기기에서 같은 파일을 고쳤을 때 생기는 충돌입니다. 스크립트는 자동으로
`rebase --abort` 하고 멈춥니다 (내용을 임의로 덮어쓰지 않습니다).
직접 해결하세요.

```powershell
cd "C:\Users\0328m\Programming Study"
git status
git pull --rebase        # 충돌 파일을 편집기로 열어 정리
git rebase --continue
git push
```

**동기화가 멈춘 것 같다**
락 파일(`.git\autosync.lock`)이 남았을 수 있습니다. 보통은 스크립트가
락 주인 프로세스가 죽었는지 확인하고 알아서 넘겨받으므로 그냥 두어도
됩니다. 그래도 안 풀리면 직접 지우세요.

```powershell
Remove-Item "C:\Users\0328m\Programming Study\.git\autosync.lock"
```

**자동 태스크가 안 뜬다**
`Ctrl+Shift+P` → `Tasks: Manage Automatic Tasks` → `Allow Automatic Tasks`.

**커밋이 너무 자주 쌓인다**
`.vscode/tasks.json` 의 자동 동기화 태스크 `args` 에
`"-IdleSeconds", "120"` 을 추가하면 2분으로 늘어납니다.
